## Общий стандарт всех моделей — low → final

Новые модели и перенос уже подготовленных используют
[MODEL_DELIVERY_STANDARD.md](docs/MODEL_DELIVERY_STANDARD.md): master сохраняется,
клиент сначала показывает лёгкий GLB, затем подгружает оптимизированный final;
серверный PNG использует final. Документ задаёт подготовку, загрузку, совместимость
rig / UV / состояний, сетевой контракт, бюджеты, проверки и план переноса.
Сейчас рабочий эталон — новая страница бутылки; остальные модели ещё не переведены.

На новой странице бутылки реализована
[отдельная доставка скинов](docs/SKIN_DELIVERY_DESIGN.md): GLB геометрии +
skin manifest + общие low / final PNG. Публичные setSkin / getSkin / getSkins
переключают 9 цветов без повторной геометрии; серверный PNG использует тот же скин.
Стартовый пакет — 196 162 байта, полная цепочка low → final — 1 534 577 байт.

[Список видов и настройки камер](docs/CAMERA_VIEW_DELIVERY.md) приходят отдельным
JSON/API. Источник — `config/camera-views/bottle.json`; порядок, названия и параметры
можно обновлять без сборки JS и повторной загрузки GLB / скинов.

[Свет, окружение, фон и тени](docs/SCENE_DELIVERY.md) вынесены в отдельный
профиль сцены. `/api/scenes/default` выбирает его через `config/scenes/default.json`.
Публичные `sceneReady`, `getScene`, `getSceneProfile`, `setScene` и PNG версии 3
используют одну ревизию / SHA-256; изменение сцены сохраняет модель и камеру.

[Камеры композиции](docs/COMPOSITION_CAMERAS.md) используют общие габариты группы
с учётом root / member-преобразований. Общие виды и детали primary задаются JSON;
getComposition / getCompositionBounds / setComposition и PNG версии 4 передают
один состав. На странице по умолчанию одна бутылка; группы подготовленных
экземпляров доступны через API. Другие модели требуют регистрации их адаптеров.

## Запуск

Приложение — в `app/`, DevOps-оснастка — в `ops/`, документация — в `docs/`.
Подробнее: [`ops/README.md`](ops/README.md), [`docs/setup/`](docs/setup/README.md).

### Демон (рабочий цикл)
```
ops/bin/start          # поднять демон в фоне: web :5180 + renderer :5181
ops/bin/rebuild        # после правок кода — пересобрать и переката́ть в демон (в фоне)
ops/bin/health         # проверить оба сервиса
ops/bin/stop           # остановить
```
Демон on-demand: работает, пока не остановишь; после перезапуска Docker/ПК сам не
поднимается (нужно авто-поднятие — раскомментируй `restart: unless-stopped` в
`ops/docker/docker-compose.yml`).

### Команды (пульт `ops/bin/`, запускать из корня репозитория)

| Команда | Что делает |
| --- | --- |
| `ops/bin/up` | Собрать образ и поднять web (:5180) + renderer (:5181), приоритетный режим |
| `ops/bin/start` | То же в фоне (= `up -d`) |
| `ops/bin/stop` | Остановить и убрать контейнеры/сеть (volume `uploads` сохраняется) |
| `ops/bin/build` | Пересобрать образ |
| `ops/bin/rebuild [svc]` | Пересобрать образ и переката́ть в поднятый демон (в фоне); рабочий цикл при изменениях кода |
| `ops/bin/health` | Проверить `/api/health` обоих сервисов |
| `ops/bin/dev` | Dev на хосте (Node ≥22; при первом запуске сам `npm ci`) → :5180 |
| `ops/bin/dev front` | Dev на хосте, только фронт с HMR → :5173 |
| `ops/bin/dev docker` | Dev в контейнере с синхронизацией `app/` ↔ контейнер; в фоне; сначала останавливает web/renderer (:5180), печатает статус и логи |
| `ops/bin/sh [web\|renderer]` | Зайти внутрь контейнера |
| `ops/bin/logs [svc]` | Логи сервиса (follow) |
| `ops/bin/test` | Юнит-тесты в контейнере (стадия `deps`) |

Единый вход через локальный прокси (роутинг `/api/render` → renderer):
`docker compose -f ops/docker/docker-compose.yml --profile edge up` → `http://127.0.0.1:8080`.

### Dev на хосте без пульта
```bash
cd app
npm ci                   # Node ≥22 (.nvmrc=22)
npm run dev:bottle       # сервер + API + рендер → http://127.0.0.1:5180/bottle.html
# npm run dev            # только фронт → http://127.0.0.1:5173
# npm run setup:browser  # разово, если нужен серверный PNG (Chromium)
```

Страницы: `/bottle.html` — одна бутылка + публичный API + серверный PNG; `/` —
мультипродукт-студия (`?model=endo|pillow|mug|pen|notebook`). Зависимости
зафиксированы в `app/package-lock.json` (`npm ci`), требуется Node.js ≥ 22.12.


## Контроль качества кода — 2 ноября 2026

Проверена текущая ветка `codex/bottle-public-api`: новая бутылка, прежние шесть
товаров и пары, загрузка / освобождение моделей, логотипы, локализация, публичные
контракты, HTTP и серверный Chromium. Опубликованный Pages-стенд не менялся.

Исправления:

- Общие безопасные чтение / сохранение языка вместо семи копий. Отказ или
  переполнение localStorage больше не ломает страницы.
- Транспорт проверяет параметры до сети, ограничивает фактически прочитанное
  тело и отменяет соседние Range-запросы после окончательного отказа. Учтены
  распакованные ответы gzip / br и несовпадение Content-Length.
- Загрузчики отклоняют пустую геометрию, сохраняют AbortError и освобождают
  ресурсы один раз. Размонтирование прежнего каталога / пары отменяет их сеть.
- Общий HTTP-reader возвращает 413 до закрытия соединения. Валидация Origin,
  точный JSON MIME, невозможные камеры и внутренние 500 имеют явные ответы.
- Серверный рендер восстанавливается после отключения Chromium; deadline
  включает запуск и context. Поздние ресурсы закрываются после отмены,
  очередь не запускается заново при остановке.
- У окружения и накопителя теней разные React keys. PMREM подготавливается до
  отрисовки материалов; вспомогательные источники исключены из beauty-прохода.
  Регрессионный тест проверяет PNG с цветным логотипом, без него и после возврата.
- Один E2E-конфиг запускает настоящий API + frontend, использует установленный
  браузер и выбирает только браузерные `*.spec.ts`. Node-тесты выполняются отдельно.
  Хешированные PNG имеют одинаковый immutable cache в dev и production.
- Устаревшие тесты приведены к принятым четырём видам корпуса и высоте страницы
  по содержимому. Движение изделия и подготовка камеры измеряются отдельно;
  ограничения контакта с полом, кадров и времени самого движения сохранены.

Результаты после исправлений:

| Проверка | Результат |
| --- | --- |
| `npm run test:unit` | 129/129 |
| Строгий TypeScript / production build | Успешно |
| Весь E2E-набор, API + Vite | 80 прошли; один тест скорости перенесён на собранную версию |
| Повтор нового контура на локальной production-сборке | 61/61, без пропусков |
| Синтаксис MJS / Python | 37 / 14 файлов, без ошибок |
| `npm audit` | 0 уязвимостей установленных зависимостей |

В режиме 200 000 байт/с и задержки 120 мс low стал доступен примерно за 10,08 с
от навигации, включая frontend и GPU-подготовку. До завершения final удалось
открыть бутылку; после загрузки качество стало high. Это эмуляция сети в Chromium
на текущем Mac. Локальный собранный сервер на 5181 также прошёл девять прямых HTTP-
проверок, включая 206 с точными байтами GLB и JSON-ответы 400 / 403 / 413 / 415.
Логи, снимки и диагностические данные — `.cache/qa/engineering-v01/`:
актуальные прогоны `unit-final.log`, `browser-final.log`, `production-tests.log`,
`build-final.log`; сводка — `verification.json`. Прежние неуспешные прогоны
сохранены как данные диагностики.

Остаются предупреждение R3F о `THREE.Clock` и предупреждение сборщика об общем
3D-модуле 1 006,97 КБ (оценка gzip сборщиком — 273,65 КБ; локальный Node отдаёт JS
без сжатия). Они не скрывались; версии библиотек и
порог предупреждения не менялись. Физические Safari / iPhone / Android и иной
сервер в этой проверке не проверялись; Blender-ассеты не пересоздавались.
Прежние отдельные `BottleStudio`, `EndoStudio`, `PillowStudio` и compatibility-

## Эксперимент с одной бутылкой — 29 октября 2026

Экран показывает один активный предмет. По следующему запросу владельца над состоянием добавлены три кнопки выбора товара; второй экземпляр и технический показатель занимаемого пространства остаются за пределами этого экрана. Старые ссылки вида `?model=bottle&second=bottle` открывают одну бутылку; параметр `second` удаляется из адреса.

Панель содержит четыре последовательных решения: состояние → цвет → логотип → нанесение. Камера управляется кнопками рядом с моделью:

| Состояние | Ракурсы |
| --- | --- |
| Стоит | Hero, корпус средней крупности, три четверти, логотип |
| Стоит без крышки | Hero с отдельной крышкой, корпус, высокий вид, логотип |
| Лежит | Hero по диагонали, средний план, высокий вид с другой диагональю, логотип |

Смена состояния проигрывает движение изделия и завершает его общим видом. Отдельные ракурсы плавно меняются примерно за 0,7–1,4 с: время зависит от поворота, изменения крупности и смещения центра, с учётом пропорций окна; настройка reduced motion отключает движение. Ручное вращение снимает выделение кнопки, следующий выбор ракурса возвращает камеру к нему. Цвет, файл логотипа и технология не сбрасывают камеру. При выборе места нанесения камера приближает это место. Ракурсы «Логотип», «Крышка» и «Горлышко» намеренно показывают деталь крупно; предмет целиком доступен в общем виде.

Лежащая — перспективная диагональ −25°, горизонтальный профиль и верхняя диагональ −35°. В крупном плане лежащего логотипа камера повёрнута на −90°, поэтому надпись читается прямо без изменения позы и нанесения.

### Анимированные состояния бутылки

Кнопки состояния управляют одной непрерывной сборкой из корпуса и отдельной крышки. Исходные Blender/GLB и их три статических позы сохранены; во время движения модели не подменяются.

| Переход | Действие | Длительность |
| --- | --- | --- |
| Стоит → без крышки | Откручивание, извлечение выше горлышка, дуга в сторону, мягкая посадка рядом | 1,28 с |
| Без крышки → стоит | Подъём, совмещение, опускание и закручивание | 1,18 с |
| Стоит ↔ лежит | Подготовительное покачивание, перенос веса через опору, ускорение, короткое затухание; обратное поднятие | 1,12 с |
| Без крышки → лежит | Сначала крышка закрывается, затем бутылка укладывается | 1,64 с |
| Лежит → без крышки | Сначала бутылка поднимается, затем снимается крышка | 1,68 с |

В таблице указано время движения изделия. При выходе из крупного плана камера
сначала расширяет кадр за 0,60–0,85 с. Диагностика `data-motion` разделяет
`actionDurationMs` и `framingDurationMs`; их сумма — `durationMs` полного перехода.
При reduced motion обе части равны нулю.

По следующей правке владельца темп немного замедлен, а фаза откручивания выделена отдельно: полный поворот занимает около 0,5 с. До освобождения крышка остаётся соосной горлышку; перенос и наклон начинаются после этого. При укладывании подготовительное движение стало спокойнее, угловая скорость растёт перед контактом, остановка короче. Остаточный качок после контакта уменьшен с 2,2° до 0,6°, следующий перебег — с 0,35° до 0,06°. Посадка крышки теперь заканчивается без дополнительного подскока. Камера использует те же часы и замедляется вместе с предметом.

Крышка вращается вокруг своего центра. Высота опоры вычисляется по реальным вершинам, включая повёрнутую крышку; опора корпуса сохраняется на полу. Крышка сначала освобождает горлышко и только затем переносится в сторону. Камера немного отъезжает, сопровождает движение и приходит к общему виду нового состояния. Выход из крупного плана плавно расширяет кадр; поворот камеры распределён по всему действию. Тени обновляются вместе с геометрией. Это постановочная кинематика по заданным траекториям, не универсальный физический движок.

Во время короткого перехода заблокированы новые состояния, ракурсы, смена места нанесения и PNG — повторное нажатие не обрывает движение. Цвет, файл и технология сохраняются и могут меняться. Статус действия находится на месте подписи ракурсов, без новой панели. При `prefers-reduced-motion: reduce` та же сборка сразу принимает конечную позу и камера переходит к ней без анимации. В покое цикл кадров останавливается.

Кинематика — `src/bottleMotion.ts`, траектория камеры — `src/bottleCameraMotion.ts`, воспроизведение и динамические тени — `src/BottleScene.tsx`; `SourceStage` в `SourceScene.tsx` сохраняет общие свет, окружение и экспорт. Актуальные прогоны темпа и веса — [runs.json](.cache/qa/bottle-motion-weight-20261029/runs.json), [откручивание](.cache/qa/bottle-motion-weight-20261029/closed-to-open-trace.json), [укладывание](.cache/qa/bottle-motion-weight-20261029/closed-to-lying-trace.json). На этом Mac шесть переходов дали 68–102 отрисованных кадра; это не гарантия частоты кадров другого устройства. Результаты предыдущего варианта, включая doming и узкие раскладки, сохранены в `.cache/qa/bottle-motion-20261029/`. Визуальная приёмка нового темпа владельцем ещё не проводилась.

Туннель передаёт локальный Host, проверка имён хостов Vite включена.

Остановить показ досрочно:

```bash
npm run share:stop
```

Команда остановки завершает туннель, отдельный предпросмотр и временное предотвращение автосна. Повторный запуск при активном показе отклоняется. Состояние — `.cache/share/session-current.json`, журнал — `.cache/share/share-preview.log`. Команда остановки проверяет принадлежность PID этому запуску. Автоотключение через 48 часов удалено; `expiresAt` равен `null`.

Живой процесс сам по себе не считается работающей ссылкой. Скрипт проверяет внешний HTTP-ответ и HTML стенда при подключении и раз в минуту; `share:status` дополнительно делает свежую проверку. Пустая страница, HTTP 502 или страница провайдера означают `unavailable`, завершившийся процесс — `offline` или `failed`. Ошибка соединения при запуске в течение 90 секунд завершает неудачный запуск.

Mac должен оставаться включённым, с интернетом и питанием. На время показа `caffeinate` предотвращает автоматический сон; экран может погаснуть. Ручной сон, выключение, перезагрузка и закрытие крышки могут прервать показ. Системные настройки питания не изменяются.

У бесплатного ngrok нет ограничения времени работы endpoint, но действуют квоты **1 ГБ исходящего трафика и 20 000 HTTP-запросов в месяц**. Аккаунту назначается dev-домен. Доступ зависит от работающего Mac, сети и провайдера; после отключения клиента показ прекращается. Изменения приложения появляются после повторной `npm run build` и обновления страницы посетителем.

Для текущего сетевого окружения конфигурация агента использует существующий локальный SOCKS-прокси Happ `127.0.0.1:10808`. Настройки DNS/VPN и системные настройки сети не меняются. Служебный API ngrok привязан только к `127.0.0.1:4048`, инспекция HTTP-запросов и удалённое управление агентом отключены.

GLB скачиваются запросами Range по 1 МиБ, не больше двух одновременно. Так крупные модели проходят через туннель без одного долгого ответа, который может оборваться. Каждый фрагмент проверяется по `Content-Range` и длине; оборванный запрос повторяется один раз. На один запрос отведено 20 секунд. Если сервер не поддерживает Range, принимается обычный полный ответ. Байты и текстуры моделей не изменяются.

Клиент ngrok **3.39.11**, macOS ARM64, установлен только в `.cache/tools/ngrok/ngrok` из [официального архива](https://bin.ngrok.com/c/bNyj1mQVY4c/ngrok-v3-stable-darwin-arm64.zip). Подпись проверена: Developer ID Application `ngrok, Inc. (TEX8MHRDQ9)`, цепочка Apple Root CA. Глобальная установка и системная служба не создавались. Личный глобальный конфиг ngrok не используется.

Также локально установлен `cloudflared` **2026.10.1**, macOS ARM64: `.cache/tools/cloudflared/2026.10.1/cloudflared`. [Официальный архив](https://github.com/cloudflare/cloudflared/releases/download/2026.10.1/cloudflared-darwin-arm64.tgz) проверен по SHA-256 `647615df99d49cd179ea5e13ef760b9bbfb33630f6ae62f87e33dfadda60adcc`. В текущей сети Cloudflare не установил рабочее соединение по HTTP/2 и QUIC; рабочее подключение ngrok требует авторизации владельца. Глобальная установка, системная служба и изменения DNS/VPN не выполнялись.

Прежний бесплатный Pinggy ограничен 60 минутами. Анонимный проброс Serveo фактически истёк примерно через 10 минут и вернул пустой HTTP 502 при ещё живом SSH-процессе. Эти варианты больше не используются для длительного показа. Плановый локальный срок 48 часов не продлевал срок ссылки у провайдера.

## Поведение

- Интерфейс на немецком и английском. При первом открытии выбран **Deutsch**, второй переключатель — **English**; на телефоне они подписаны DE / EN. Выбор языка сохраняется в локальном хранилище браузера. Смена языка переводит подписи, подсказки и ошибки, сохраняя изделие, ракурс, логотип и область нанесения.
- 3D и настройки находятся в одной рамке. На экранах шире 960 px они стоят рядом с одинаковыми верхней и нижней границами; на меньших — в одной колонке. При высоте окна от 700 px мобильный 3D-просмотр остаётся сверху во время прокрутки настроек, чтобы сразу видеть изменение нанесения. На невысоких десктопах отступы уплотняются. Панель разделена на три шага: изделие, логотип и позиция. Карточки областей содержат мини-схемы; размеры указаны в миллиметрах.
- Кружка, ручка и блокнот выбираются тремя кнопками. Загруженный логотип сохраняется при переключении; выбранная область запоминается отдельно для каждого изделия до перезагрузки.
- Изделие вращается мышью или касанием, колесо/жест приближает его. При загрузке изделия камера показывает нужную сторону на максимальном отдалении. Ручка появляется по диагонали: наконечник внизу слева, кнопка сверху справа, как на референсе владельца.
- Ручка вращается вокруг середины корпуса, в 70 мм от наконечника, блокнот — вокруг центра обложки, в 105 мм от нижнего края. Закладка и клип не смещают опору. Камера и приближение сохраняют этот центр при ручном вращении и возврате к нанесению; предмет не обходит кадр по дуге вокруг края. Для этих двух изделий вращение замедлено, инерция короче, наклон ограничен высотой взгляда 15–75° над полом. Панорамирование отключено. Максимальная дистанция для всех изделий — 12 единиц сцены.
- При выборе зоны камера плавно поворачивается из текущего ракурса к нанесению по короткой дуге, сохраняя приближение. Обычно переход занимает 0,38–0,6 секунды; при низкой частоте кадров он длится дольше, чтобы избежать скачка в конечное положение. Повторный выбор другой зоны продолжает движение из достигнутого положения; вращение или масштабирование вручную сразу прерывает автоповорот. «Без нанесения» скрывает логотип и сохраняет текущий ракурс.
- Круглая кнопка внизу 3D-окна плавно возвращает вид к выбранному нанесению и максимальному отдалению, сохраняя опорную точку. При «Без нанесения» используется ракурс области по умолчанию. Настройка системы «уменьшить движение» отключает автоматическую анимацию камеры и интерфейса.
- Все изделия касаются пола бесшовной циклорамы; освещение и тени рассчитываются в Three.js. Блокнот лежит обложкой вверх, резинка справа, закладка снизу слева. У ручки и блокнота направленная тень дополнена мягкой контактной тенью от геометрии корпуса. Она пересчитывается при смене модели и сохраняется при вращении камеры; логотип в её расчёте не участвует. Матовый пол освещается источниками сцены, чтобы световое окружение для металлических деталей не засвечивало контакт. Сам 3D-предмет остаётся неподвижным на полу.
- PNG, SVG, JPG и WebP до 10 МБ можно выбрать кнопкой или перетащить в область загрузки; они обрабатываются в браузере. Прозрачный фон сохраняется, непрозрачный автоматически не удаляется. Некорректный файл не заменяет уже выбранный логотип.
- Логотип вписывается в выбранную область с сохранением пропорций. Свободного перемещения, масштаба, поворота и перекрашивания изделия нет.
- Кружка: без нанесения; SIDE TS 92 × 200; ROUNDSCREEN 80 × 130; FRONT PAD, BACK PAD и напротив ручки 35 × 45 мм. В подписях её схемы размеры идут как высота × ширина. Понятные названия в немецком интерфейсе: «Rundum · groß», «Rundum», «Vorderseite», «Rückseite», «Gegenüber dem Henkel»; параметры исходной спецификации сохранены.
- Ручка: без нанесения или рядом с клипом, максимум 40 × 6 мм. Логотип располагается на месте надписи с референса и отображается светлым металлическим силуэтом по альфаканалу, имитирующим лазерную гравировку; цвет файла не переносится. Непрозрачный фон не удаляется. Корпус без нанесения чистый, без встроенного «YOUR LOGO».
- Блокнот: без нанесения или на лицевой обложке, максимум 100 × 150 мм, полноцветная цифровая печать. Область зафиксирована по центру, левее резинки, и следует форме обложки. Цвета и прозрачность логотипа сохраняются. Длинная сторона текстуры ограничена 4096 пикселями.
- PNG содержит текущий ракурс изделия и циклораму; имя файла включает изделие и выбранную зону. Панель управления в PNG не попадает.
- После перезагрузки логотип и области сбрасываются; изделие выбирается из параметра `model` в URL. Нет загрузки 3D-файлов через интерфейс, внешних API, аккаунтов, базы данных и отправки логотипов на сервер.

## Модели и спецификации

Канонические спецификации — [кружка](models/mug/SPEC.md), [ручка](models/pen/SPEC.md) и [блокнот](models/notebook/SPEC.md). Параметры, которые читает приложение, — `models/<изделие>/specification.json`; карточки владельца сохранены рядом как `specification.png`.

Владелец согласовал временную высоту кружки **96 мм** и длину ручки **140 мм**. Диаметры по пропорциям Meshy: **80,267734 мм** и **9,480297 мм** соответственно. Физические габариты товаров и числовые отступы печати пока не подтверждены. Это визуальные макеты, а не производственные файлы. Все зоны в интерфейсе фиксированы.

Исходные FBX и четыре PNG сохранены в `models/mug/source/`. Они не перезаписывались. Для FBX восстановлены связи с приложенными PBR-картами; GLB содержит все текстуры. Оригинальная UV и окраска кружки сохранены. Поверх внешней стенки подготовлена отдельная цилиндрическая поверхность для прозрачного логотипа; она не изменяет материал корпуса.

Исходники ручки сохранены в `models/pen/source/`. По просьбе владельца рабочая ручка реконструирована по `models/pen/reference.png` с ровной геометрией и чистыми процедурными материалами: повреждённые Meshy-карты и встроенная надпись в веб-модели не используются. Положение нанесения восстановлено по фотографии; центр фиксирован на 94 мм от наконечника. Оригиналы сохранены отдельно.

Исходники блокнота сохранены в `models/notebook/source/`. Для макета принята обложка A5 **148 × 210 мм**, толщина по модели **14,476406 мм**. Это допущения для предпросмотра. Сохранены исходная геометрия, цвет и фактура; материал сделан матовым. Карты цвета и нормалей встроены без изменения пикселей. На исходной обложке не обнаружена встроенная надпись. Поверхность для логотипа проецируется на реальную обложку, её размер 100 × 150 мм.

URL модели содержит версию по SHA-256 GLB. После пересборки ассета открытый стенд подгружает новую версию, сохраняя выбранный логотип.

Старый `public/models/demo-notebook.glb` остаётся отдельной служебной заготовкой и в интерфейсе не используется.

## Плавность переходов — 30 октября 2026

Все три студии используют общую камеру `src/studioCameraMotion.ts`: кратчайший поворот, изменение дистанции в логарифмическом масштабе, адаптивную длительность и непрерывные положение, скорость и ускорение при смене цели. У подушки удалены остановки между отъездом, обходом и приближением. Программное движение больше не получает дополнительный шаг от оставшегося инерционного вращения OrbitControls. Ручной жест отменяет перелёт; выбор текущего установленного вида не двигает камеру. PNG доступен после остановки камеры.

Перед сменой состояния бутылки из крупного плана добавлено 0,60–0,85 с на спокойный отъезд; только после него начинается прежняя предметная кинематика. Из общего вида дополнительной задержки нет. Геометрия, материалы, освещение, зафиксированные ракурсы и сами траектории предметов сохранены.

## Единый экран SOURCE — 30 октября 2026

`src/ProductStudio.tsx` объединяет три товара. В правой панели над состоянием всегда видны три кнопки с пиктограммами: Flasche / Endo / Kissen, в английском интерфейсе — Bottle / Endo / Pillow. Кнопки остаются над прокручиваемыми настройками; после смены товара настройки начинаются сверху. У подушки показана её единственная расцветка и материал. На узком экране просмотр и панель идут в обычном потоке страницы: старое закрепление viewport отключено только для общего экрана, чтобы он не закрывал переключатели и поля.

Один Canvas, WebGL-контекст, HDR-окружение и HDR/GTAO-композитор сохраняются между товарами. GLB загружаются в кеш текущего экрана; остальные два файла подгружаются после готовности первого кадра. Следующая модель и её 48 кадров мягкой тени готовятся под снимком текущего кадра. Затем происходит плавное перекрытие за 180 мс на одинаковом фоне. При reduced motion предыдущий кадр удерживается до готовности, затем заменяется сразу. Серия быстрых нажатий запоминает последнюю цель; текущая подготовка заканчивается перед следующим переходом. Повторный выбор активного товара ничего не перезапускает. При ошибке загрузки остаётся предыдущий товар и доступна повторная попытка.

Для каждого товара отдельно сохраняются состояние, цвет, зона / технология / число красок, логотип и фиксированный ракурс в пределах открытой страницы. Возврат из ручного свободного вращения начинает с Hero. Переключение во время предметной анимации прерывает её под удержанным кадром; при возвращении товар находится в последнем выбранном конечном состоянии. Поле логотипа обрабатывается для того товара, на котором началась загрузка. Глобальный язык общий; смена языка не пересоздаёт сцену. URL обновляется через history без перезагрузки, прямые `?model=bottle`, `?model=endo`, `?model=pillow` открывают общий экран с выбранным товаром. Явные прежние двухтоварные ссылки Endo / Pillow сохранены.

Для показа создаётся временный экземпляр графа модели; Endo клонируется вместе со скелетом из исходной bind pose. Это предотвращает накопление поворотов после повторного входа. Текстуры и основная геометрия переиспользуются; временная текстура костей освобождается при уходе. Экспорт PNG использует текущую сцену и блокируется до готовности нового товара. Принятые GLB, карты, камеры, свет и траектории предметов не редактируются.

Один `data-studio-instance` и возрастающий `data-render-frames` подтверждают сохранение Canvas между переключениями; реальные источники и экспозиция сохраняются.
