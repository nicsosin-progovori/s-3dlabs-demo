# Одна бутылка и публичный API

Дальнейшее применение low → final ко всем моделям зафиксировано в
[общем техническом стандарте](MODEL_DELIVERY_STANDARD.md). Статус остальных
товаров и порядок их переноса находятся в его разделе 11.

## Цель и границы

Новая страница `/bottle.html`: только бутылка MO9431, три состояния, готовые
камеры и скачивание PNG. Позже владелец явно расширил UI цветами, логотипом,
нанесением и DE/EN — реализация описана в последнем разделе этого плана.
Сцена не содержит элементов управления. Кнопки и
консоль используют один объект `window.appName3DVisualisation`.

PNG рассчитывает наш сервер по фактической камере и состоянию. На этапе
разработки сервер локальный; в production используется тот же HTTP-контракт.
Клиент не отправляет снимок canvas. Модель, материалы, свет и предметная
анимация используются из прежней разработки.

Предыдущий стенд с тремя товарами и режимом пары сохраняется на `/`.
Публикация, staging, commit и push в эту задачу не входят.

## Критерии приёмки

- На новой странице нет выбора товара, пары, цвета, файла логотипа и нанесения.
- Кроме состояний, видов и скачивания PNG на странице нет других интерактивных
  элементов; логотип в шапке не является ссылкой.
- Ни одна кнопка не находится внутри компонента визуализации.
- Все действия кнопок воспроизводятся через публичный API из консоли.
- Каждый готовый вид вызывает единственный публичный `setCamera(camera)`.
- Экспорт использует фактическую камеру после ручного движения, включая оптику,
  ориентацию и пропорции кадра. Сервер заново загружает свой ассет и рендерит его.
- Проверка подтверждает, что PNG получен с backend, а не из canvas клиента;
  серверная камера совпадает с переданной. Ошибка backend не вызывает подмену
  клиентским снимком.
- Прежний одиночный и парный стенд открывается и работает в новой ветке.
- Изменения остаются локальными до отдельного решения владельца о доставке.
