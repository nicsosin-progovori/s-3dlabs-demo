# Архитектура: движок + объекты по ID

Цель: приложение-движок, которое **грузит объекты по ID и рендерит их**, с данными
объектов отдельно от кода. «Всё скомпилено в проект» не масштабируется (миллионы
объектов × сотни сцен/превью). Встраивание в чужие сайты / iframe — НЕ цель.

## Суть
- **`app/`** — движок: берёт объект, читает его `manifest.json`, интерпретирует
  (геометрия+скины+сцена+камера) и рендерит (живьём и серверным PNG). Константен.
- **`objects/<id>/<revision>/`** — данные объекта, отдельно, по ID. Это
  «подрасчётная/скомпилированная под объект база», но вне движка.
- Движок грузит объект **по ID в рантайме**, не через compile-time импорты.

## Пакет объекта (реализовано для bottle/v01)
```
objects/<id>/<revision>/
  manifest.json   — единая точка входа: что входит, пути + sha
  geometry/ · skins/ · textures/ · scene/ · camera/ · spec/
```
Собран `objects/bottle/v01/` копией ассетов студии (студия не тронута): 39 файлов,
6 частей, 8.7M. Бинарники (GLB/PNG) в git не идут, манифесты/структура — видны.

## Что меняется в движке (суть работы)
1. **Данные наружу:** убрать compile-time импорты (`import … from '../models/…json'`)
   → рантайм-загрузка `objects/<id>/manifest.json` и далее по ссылкам.
2. **Снять хардкод `bottle`:** контракты зашиты на `modelId:'bottle'`; движок должен
   принимать любой ID и управляться манифестом. Externalization и generic-движок — вместе.

## Миграция (без поломки студии)
1. ✅ Собрать `objects/bottle/v01/` копией (сделано).
2. Рантайм-загрузчик по ID: читает manifest, грузит, рендерит.
3. Снять хардкод `bottle` → id-driven (второй объект тем же движком).
4. Перевести студию на загрузку по ID, выпилить ассеты из `app/`.
5. Позже: `objects/` в сторейдже (ключ+подпись), превью-галереи, защита.

## Масштаб (почему это закрывает требования)
Миллионы объектов — данные в сторейдже, движок константен · сотни сцен/превью — в
пакете + пред-рендеренные галереи · динамический рендер — по ID (есть) · защита —
fetch по ключу (подпись/ACL) · LOD/текстуры — профили low/final по требованию ·
бесшовно — прогрессивно low→final, кэш по sha.
