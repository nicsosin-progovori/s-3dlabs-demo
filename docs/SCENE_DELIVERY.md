# Отдельная доставка сцены: свет, окружение и тени

Дата: 02.11.2026. Реализовано на `/bottle.html`.
Активная студия приходит отдельным JSON/API, независимо от geometry GLB,
скинов, списка камер и JavaScript-сборки. Перенесена принятая студия без
изменения её художественных параметров; версия движка — `source-studio-v01`.

## 1. Файлы и HTTP

| Назначение | Источник |
| --- | --- |
| Указатель активной сцены | `config/scenes/default.json`, 49 байт |
| Принятый профиль | `config/scenes/source-studio/v01/scene.json`, 2 623 байта |
| Схема и общая проверка | `shared/sceneContract.mjs` / `.d.mts` |
| Чтение профилей и API | `server/scenes.mjs` |
| Клиентский загрузчик | `src/sceneLoader.ts` |
| Адаптер данных к Three.js | `src/studioScene.ts` |
| Свет / окружение / тени / постобработка | `src/StudioStage.tsx` |

`GET /api/scenes/default` читает указатель, затем возвращает полный профиль.
Дополнительного клиентского запроса к указателю нет. `GET /api/scenes/<id>/<revision>`
возвращает конкретный профиль. Node читает файлы на каждый запрос: добавление
ревизии и переключение указателя не требуют сборки JS или перезапуска сервера.
В открытой странице профиль самопроизвольно не меняется; polling отсутствует.
Для отдельно размещённого frontend адрес API выбирается через meta-настройку
из [BOTTLE_API.md](BOTTLE_API.md). SHA-256 проверяется так же, а CORS backend
открывает клиенту заголовки fingerprint.

Ответ содержит исходные JSON-байты, `X-Scene-SHA256`, `X-Scene-Revision`,
`ETag`, `Cache-Control: no-cache`. Поддерживаются HEAD и условный 304.
Другой метод даёт 405, отсутствующая ревизия — 404, повреждённые данные — 503.
Ответ не раскрывает путь или содержимое ошибочного файла. Запрос метаданных
не запускает Chromium и не занимает очередь PNG.

## 2. Профиль и границы движка

Полный пример — [scene.json](../config/scenes/source-studio/v01/scene.json).
Корень: `schemaVersion: 1`, `id`, `revision`, `engine`, `coordinates`, `settings`.
Указатель содержит только `id` / `revision`. Профиль ограничен 64 КиБ,
указатель — 512 байт; id и revision не допускают пути, URL и исполняемые выражения.
Неизвестные поля и несовместимые данные отклоняются целиком.

В `settings` доставляются:

- Основной, заполняющий, окружающий и полусферический свет: положения,
  цели, цвет, интенсивность.
- Окружение для отражений: фон, размер карты и параметры софтбоксов.
  Поддерживается 1–12 софтбоксов, в принятой студии четыре. Внешняя HDR-карта
  в этой версии не требуется и её загрузчик не добавлен.
- Цвета фона / пола, экспозиция, длительность появления. CSS-подложка
  рассчитывается из тех же параметров с учётом ACES, что и 3D-фон.
- Площадная / контактная тень: радиус, контактная доля, плотность, непрозрачность,
  цвет, положение и размер приёмника, число кадров / источников, разрешение карт.
- Основная и напольная карты теней: разрешение, bias, normalBias.
- GTAO: интенсивность, радиус, толщина, число проб и масштаб расчёта.

Движок фиксирует ACES Filmic, sRGB и BasicShadowMap с принятым PCSS-фильтром;
алгоритмы, GLSL, геометрия циклорамы, диапазон shadow-camera и denoise остаются
кодом версии движка. JSON выбирает поддержанные параметры, а не произвольный
рендерер или программу. Новый алгоритм / тип сцены требует адаптера и проверок.

Координатный договор: модель в метрах, `worldScale: 12`, Y вверх, фронт +Z,
контактная плоскость Y=0. Положения света задаются уже в координатах отрисовки,
после масштабирования модели; повторно умножать их на 12 нельзя. Приёмник тени
в принятом движке находится на Y=0,002. Численная проверка подтвердила охват
реальных поз и переходов бутылки shadow-camera принятой студии.

Тени не поставляются готовой картинкой: они вычисляются по геометрии, позе,
свету и приёмнику. Поворот, снятие крышки, замена low на final и смена сцены
используют живой расчёт / обновление теней. Прежний PCSS-фильтр материалов
и временная смена теней во время предметной анимации сохранены.

## 3. Клиент и готовность

Начальные запросы сцены, модели / скина и видов запускаются независимо.
`sceneReady` завершается после загрузки и проверки JSON. `ready` завершается
после показа low с выбранной сценой, окружением, тенями и постобработкой.
До получения сцены принятая студия не подменяется встроенным освещением.
Ошибка первой загрузки отклоняет оба Promise и выводит ошибку подготовки.

После первого показа прежняя цепочка low → final продолжается в фоне.
Смена сцены загружает / проверяет новый JSON и ждёт окончания жеста,
предметного / камерного движения и перехода качества. Затем обновляет сцену
в том же Canvas, пересчитывает окружение / тени / AO и завершает Promise.
Геометрия, rig, поза, камера, логотип и скин сохраняются; GLB / карты товара
не запрашиваются повторно. Подготовка final учитывает изменение сцены.

Ошибка сети / JSON / hash до применения оставляет прежний профиль.
Новый выбор отменяет незавершённую загрузку старого; поздний ответ не применяется.
Уже применённая сцена заканчивает подготовку перед следующей командой.
Ресурсы прежнего окружения, фона и постобработки освобождаются при замене;
общие геометрия циклорамы и текстура софтбокса живут до закрытия сцены.

Перед первым beauty-кадром и после изменения окружения выполняется `gl.compile`:
это заранее готовит PMREM, вне отрисовки материала. Иначе вложенный PMREM-рендер
может восстановить счётчик texture units от предыдущего прохода теней и превысить
лимит GPU. Подготовка учитывает объект текстуры и её `pmremVersion`.
Источники `RandomizedLight` участвуют только в накоплении тени: beauty-проход и
PNG временно исключают их группы, затем восстанавливают видимость. Параметры
принятого света, качество карт и fingerprint профиля не изменяются.

## 4. Публичный API

```js
const app = window.appName3DVisualisation;
await app.sceneReady;            // готов профиль; модель ещё может загружаться
const ref = app.getScene();      // {id, revision, sha256}
const profile = app.getSceneProfile(); // изолированная копия либо null
await app.ready;                 // готов первый полноценный кадр
await app.setScene({id: 'source-studio', revision: 'v01'});
```

`setScene` принимает существующие `id` / `revision`, без URL и произвольного JSON.
Метод входит в ту же очередь, что состояния, камеры, скины и PNG; повторное
назначение того же fingerprint не пересоздаёт студию. Новая сцена не добавляет
элементов управления: управление сценой остаётся публичным API. По дополнительному запросу владельца
внешняя панель также содержит цвет, логотип, нанесение и DE/EN.

`sceneReady` относится к начальной загрузке; последующие изменения ожидаются
через Promise `setScene`. `getScene()` доступен после загрузки профиля, а во время
смены отражает выбранный профиль; завершение подготовки гарантирует `setScene`.
Диагностика: `data-scene`, `data-scene-revision`, `data-scene-sha256`,
`data-scene-status` у viewer; фактическая сигнатура настроек — у Canvas.

## 5. Серверный PNG и совместимость

Текущий HTTP-контракт — version 5. Правила сцены версии 3 сохраняются. Поле сцены, обязательное с версии 3:

```js
scene: {id: 'source-studio', revision: 'v01', sha256: 'полный SHA-256 JSON-файла'}
```

Клиент берёт scene из `getScene()`, камеру — из `getCamera()`.
Backend перед постановкой в очередь находит файл и сверяет hash. Если файл
изменился относительно клиента, запрос получает 409; неизвестная сцена — 404.
Другой профиль автоматически не выбирается. Worker независимо загружает
именно эту ревизию, проверяет байты / hash и использует тот же адаптер / движок.
Сервер сверяет фактические scene, skin и камеру worker с заданием.

Ответ дополняют `X-Render-Scene: source-studio@v01` и `X-Render-Scene-SHA256`.
Публичный метод также проверяет их перед возвратом Blob. Рендер использует final,
даже если клиент показывает low; клиентский capture не используется.

В одноразовом PNG worker (`StudioStage imageRender`) сначала накапливаются все
кадры теней из профиля, затем выполняется один итоговый beauty / GTAO проход.
Промежуточные beauty-кадры, необходимые интерактивному просмотру, здесь пропускаются.
Основные карты теней не рассчитываются внутри bake-pass, где интенсивность
основного света нулевая. Перед итоговым проходом они включаются и принудительно
обновляются. Сначала освобождаются только shadow targets временных
`RandomizedLight`; накопленная карта тени, основные карты, окружение и материалы
сохраняются. Сглаживание геометрии остаётся 4× MSAA в HDR composer; дублирующие
MSAA / depth у default framebuffer worker выключены, поскольку туда приходит
только fullscreen OutputPass. Параметры профиля и его fingerprint не меняются.
Этот режим предназначен для одного неизменяемого задания, не для viewer.

Потеря WebGL-контекста отклоняет задание; capture дополнительно проверяет
`isContextLost()`. Backend возвращает ошибку и закрывает неисправный браузер,
а не выдаёт чёрный PNG как успешный. Валидный PNG header сам по себе не является
проверкой качества: при размещении также проверяются пиксели и загруженный логотип.

Сырые version 1 / 2 сохранены: v1 — чёрный скин, v2 — обязательный skin.
Они используют сохранённую студию `source-studio@v01`; поле scene в них запрещено.
Это сохраняет прежнее поведение независимо от смены активного указателя.

Version 4 также передаёт [композицию](COMPOSITION_CAMERAS.md). Worker воспроизводит
все подготовленные экземпляры и их преобразования, используя выбранную сцену.
Version 3 сохраняет явную сцену и фиксированную одну бутылку. Подключение других
моделей к новому viewer / PNG требует их delivery-адаптера.

## 6. Обновление, откат и перенос

Новый выпуск создаётся отдельным `config/scenes/<id>/<revision>/scene.json`.
После проверки схемы и кадров указатель `default.json` переключается на него.
Оба файла обновляются целиком, предпочтительно атомарной заменой на том же
filesystem. Ревизии не перезаписываются: старые файлы нужны уже открытым клиентам
и их PNG-запросам. Вновь открытая страница получит новый профиль; открытая
может перейти на него явным `setScene({id, revision})`.

Откат — вернуть указатель на сохранённую ревизию. Уже открытые страницы сохраняют
выбранную сцену; для её смены нужен явный вызов API либо перезагрузка страницы.
Изменение файлов на удалённом сервере выполняется только в согласованном релизе.

Комплект приложения включает `config/scenes/` вместе с `config/camera-views/`,
`dist/`, `server/`, `shared/` и runtime-зависимостями. Одного `dist/` недостаточно.
Старый каталог / пара используют прежний профиль в коде для совместимости;
их отдельная доставка сцены и перенос других моделей этой задачей не выполнены.
Для других габаритов / пола / масштаба проверяются координаты и область теней.

## 7. Проверки

TypeScript / production build, 79 программных / контрактных тестов и все
37 браузерных сценариев прошли. Среди них — 9 новых по сцене: независимые
загрузки, ошибки, смена профиля, сохранение камеры / скина / контекста, очередь,
жест, late final и отказ PNG при несовпадении fingerprint. Прежние API, камеры,
все 9 скинов, low → final, адаптивность и старый каталог / пара также проверены.

Сравнены 5 пар серверных PNG на одних камерах: закрытая, открытая, лежащая,
макро логотипа и серебристая бутылка. Параметры принятой сцены, CSS и GLSL фона
совпали точно; средняя абсолютная разница RGB по кадру — 0,0204–0,1319 из 255.
Накопление теней использует случайные источники, поэтому побитовое совпадение
PNG не обещается. Кадры и численные результаты: `.cache/qa/bottle-scenes-v01/`.

```sh
npm run test:bottle:scenes
npm run build
```

Браузерные команды и остальные проверки — [BOTTLE_API.md](BOTTLE_API.md).
Для сравнения кадров сохранён `scripts/compare-bottle-scenes.mjs`: `--before`
снимает эталон до изменения, обычный запуск сравнивает с ним текущий сервер.
