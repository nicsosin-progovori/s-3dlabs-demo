# Камеры относительно композиции

Дата: 02.11.2026. Реализовано на `/bottle.html`.
Композиция — корневая группа с одним или несколькими участниками. Участник
может содержать составные части: бутылка включает корпус и крышку, в том числе
снятую. Общие виды рассчитываются по границам всей группы; крупные планы могут
явно выбирать основной элемент.

## 1. Расчёт

`src/compositionCamera.ts` — общий код, без зависимости от товара или GLB:

1. Получить границы видимых участников с учётом позы.
2. Применить преобразование участника и корневой группы в одном пространстве.
3. Объединить границы. Геометрический центр — `(min + max) / 2` общей области.
4. По габаритам, направлению, fov, zoom, roll, пропорциям viewer и отступам
   вычислить положение и цель камеры. Художественное смещение `subject`
   применяется после базового расчёта центра.

В расчёт передаются только явные участники. Студийный пол / фон, свет,
приёмники теней, служебные объекты и невидимые элементы не входят в границы.
Усреднение точек привязки моделей не используется. Пустая композиция запрещена.

Адаптер `src/bottleComposition.ts` использует реальные опорные вершины
канонического low rig, включая крышку и её текущую позу. Поворот и неравномерный
масштаб применяются к вершинам, затем вычисляются общие границы. Переход на final
сохраняет эти опоры и камеру. Во время предметной анимации кадр учитывает общую
область движения группы и плавно приходит к конечному виду.

`bottleFrame` теперь обёртка над общим fitter. Через неё тот же расчёт используется
и прежним режимом пары. Численно проверена композиция бутылки с трекером Endo
на телефонных и desktop-пропорциях, с креном и zoom.

## 2. Описание состава

Схема — `shared/compositionContract.mjs` / `.d.mts`. Пример одного участника:

```js
{
  schemaVersion: 1,
  id: 'main',
  primary: 'bottle',
  root: {position: [0,0,0], rotation: [0,0,0], scale: [1,1,1]},
  elements: [{
    id: 'bottle', product: 'bottle', visible: true,
    transform: {position: [0,0,0], rotation: [0,0,0], scale: [1,1,1]}
  }]
}
```

`position` — метры до общего масштаба сцены 12; `rotation` — градусы, Euler XYZ;
`scale` — три положительных коэффициента. Преобразование root применяется
к преобразованию участника, затем к позе его частей. Исходный GLB не переписывается.
JSON-преобразования преобразуются в те же матрицы при показе и серверном рендере.

Разрешены 1–8 участников с уникальными id и видимым primary. Невидимые элементы
не показываются и не влияют на центр. Позиции ограничены ±2 м, углы ±360°,
масштаб 0,05–3. Неизвестные поля, URL, некорректные числа и неподготовленные
адаптеры отклоняются. Клиент дополнительно проверяет допустимость рассчитанной
камеры для нового состава до его применения.

Число участников верхнего уровня не равно числу деталей. Снятая крышка остаётся
частью rig бутылки и учитывается в общей композиции без повторной доставки GLB.

## 3. Настройки видов

Поле frameTarget введено в schemaVersion 2 / revision v02. Текущий
`config/camera-views/bottle.json` — schemaVersion 3 / revision v03: сохраняет
12 видов корпуса и отдельно доставляет 9 видов крышки через lidStates.
Художественные параметры прежних 12 видов сохранены. Новое поле камеры:

```json
"frameTarget": "composition"
```

- `composition` — весь видимый состав; используется в общих видах.
- `primary` — основной участник, выбранный полем composition.primary;
  используется для деталей. `focusMm` задаёт локальную область этого участника,
  которая преобразуется вместе с ним и корневой группой.

`focusMm` вместе с `frameTarget: composition` запрещён. Каталог v1 продолжает
читаться: без focusMm подразумевается composition, с focusMm — primary.
Направление камеры задаётся в осях сцены; преобразования группы меняют геометрию,
её границы и центр. `subject` сохраняет принятое смещение композиции в кадре.
Все кнопки по-прежнему вызывают один публичный `setCamera(camera)`.

## 4. Публичный API

```js
const app = window.appName3DVisualisation;
await Promise.all([app.ready, app.viewsReady]);
const composition = app.getComposition(); // изолированная копия описания
const metrics = app.getCompositionBounds(); // min, max, center, size

const copy = structuredClone(composition.elements[0]);
copy.id = 'second';
copy.transform.position = [0.16, 0, 0];
composition.elements.push(copy);
await app.setComposition(composition);

await app.setCamera(app.getViews()[0].camera);
const png = await app.getCurrentViewAsImage();
```

Метрики возвращаются в координатах камеры после масштаба 12. Это канонические
границы конечной текущей позы; читать их для законченного кадра следует после
завершения Promise смены состояния / состава. Ручное смещение камеры границы
геометрии не меняет; её фактическая цель может включать художественный subject.

`setComposition` входит в общую очередь. Он ждёт окончания жеста, движения и
перехода качества, применяет состав, вписывает текущий defaultView и ждёт камеры /
теней. Предыдущее завершённое предметное движение не запускается повторно.
Смена primary сохраняет контроллер камеры. Модель, скин, сцена и Canvas остаются
доступны без повторной загрузки ассетов. Отказ валидации сохраняет прежний состав.
Один и тот же состав не пересоздаётся. Low → final и обновление каталога видов
сохраняют вручную выбранную камеру.

## 5. Серверный PNG

Текущий запрос — version 5; composition обязательна начиная с version 4. Кроме scene / skin / state / фактической camera /
image он обязательно содержит `composition` той же схемы, что `getComposition()`.
Версии 1–3 сохранены как одна бутылка с единичными преобразованиями; поле
composition в них запрещено. Правила skin и scene прежних версий сохранены.

Worker использует тот же компонент `src/CompositionActors.tsx` и те же
преобразования. Final GLB / скин загружаются один раз, каждый участник получает
собственный rig и нанесение, а геометрия / карты товара разделяются между ними.
Все участники текущего адаптера бутылки используют выбранные state, skin,
логотип и нанесение. Оформление передаётся decoration в версии 5 —
[контракт](BOTTLE_API.md#логотип-и-нанесение-через-публичный-api).

Сервер сверяет состав worker с заданием и возвращает
`X-Render-Composition-SHA256` — SHA-256 канонического нормализованного JSON.
Публичный метод проверяет hash вместе со сценой и происхождением PNG.
Положение камеры остаётся фактическим снимком: сервер не подменяет его пресетом.

## 6. Поддержка моделей

Общий fitter рассчитан на любые предметы и части, предоставляющие корректные
границы и матрицы. В новом viewer / PNG сейчас зарегистрирован подготовленный
адаптер бутылки: работают одна бутылка и группы её экземпляров. Страница
по умолчанию сохраняет одну бутылку; новых элементов управления не добавлено.

Фактическое добавление Endo или другого товара в новый viewer / PNG требует
его готового low → final / skin / pose-адаптера и регистрации в контракте /
компоненте участников. Калькулятор центра переписывать не требуется. Тяжёлый
Endo из прежнего каталога не подключён в обход стандарта доставки. Старый
каталог / пары сохраняют свой набор товаров и прежнее поведение.

Для нового адаптера обязательно: общие метры и масштаб сцены, границы всех
видимых частей в позе, стабильные опоры low → final, одинаковые преобразования
клиента и PNG, проверка целого и крупных планов на мобильных пропорциях.
Фиксированная студия имеет собственную область света / теней; большие композиции
требуют подходящего профиля сцены и проверки габаритов вместе с камерой.

## 7. Проверки

```sh
npm run test:bottle:composition
npm run build
```

Браузерные сценарии — `tests/bottle-composition.spec.ts`; общие команды —
[BOTTLE_API.md](BOTTLE_API.md). Фактические результаты прогона —
[BOTTLE_API_PLAN.md](BOTTLE_API_PLAN.md).

Проверки включают реальные вершины трёх поз, root / member-преобразования,
бутылку с трекером, целые и локальные виды, общий центр, мобильные размеры,
серверный PNG двух экземпляров с анализом пикселей, отсутствие новых GLB / карт,
жест, анимацию, late final, сохранение камеры и освобождение ресурсов.
Эталонные кадры и результаты — `.cache/qa/bottle-composition-v01/`.
