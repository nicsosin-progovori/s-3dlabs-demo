# Отдельная доставка скинов: действующая реализация

Дата: 02.11.2026. Реализовано локально на `/bottle.html`.
Скин — цвета, материалы и текстуры товара. Скелет / веса анимации (glTF skin)
остаются частью геометрической модели и не относятся к этой подсистеме.

## 1. Что теперь работает

Бутылка поставляется тремя независимыми частями:

1. Два **geometry GLB** — low и final, без изображений и внешних зависимостей.
2. **Skin manifest JSON** — материалы, их параметры, совместимость и ссылки на карты.
3. **Общие PNG** low / final — файлы с SHA-256 в имени.

Геометрия загружается по прежней системе low → final. Менять скин можно без
повторного запроса GLB. Девять цветов из исходной спецификации используют
одни и те же карты покрытия, металла и бамбука; различаются PBR-параметры.
Серверный PNG использует ту же ревизию выбранного скина на final-геометрии.

По дополнительному запросу владельца на страницу возвращены девять цветовых
кнопок: они вызывают тот же публичный setSkin. Также восстановлены логотип,
нанесение и DE/EN; [контракт оформления](BOTTLE_API.md#логотип-и-нанесение-через-публичный-api).
Все элементы управления по-прежнему находятся за пределами viewer.
Старый каталог / пара и другие товары в этой итерации не переводились.

## 2. Файлы и фактический объём

| Составляющая чёрной бутылки | Байты |
| --- | ---: |
| `bottle-geometry-low-v01.glb` | 157 476 |
| Low PNG, семь файлов | 31 987 |
| `bottle-black/v01/skin.json` | 6 699 |
| Полный стартовый пакет | **196 162** |
| `bottle-geometry-final-v01.glb` | 506 284 |
| Final PNG, семь файлов | 832 131 |
| Final + его карты + manifest | **1 345 114** |
| Вся цепочка low → final, manifest один раз | **1 534 577** |

Это объём моделей / скина, без frontend, заголовков HTTP и окружения.
Разделение само по себе не является сжатием: суммарный объём чуть больше
прежних двух GLB (1 531 748 байт). Выигрыш — смена и обновление скина без
повторной геометрии, переиспользование карт и независимое кеширование.

Защищённые исходники `bottle-low-v01.glb`, `bottle-hq-v01.glb`, `bottle.glb`
и Blender master сохранены. Первые два теперь служат входом упаковщика и
эталоном сравнения; новая страница их не скачивает. В geometry GLB побайтно
скопированы исходные геометрические bufferViews без редукции / перекодирования:
6 082 треугольника low, 21 980 final. Новых отличий геометрии не внесено.

Структура:

```text
public/models/bottle/bottle-geometry-low-v01.glb
public/models/bottle/bottle-geometry-final-v01.glb
public/skins/bottle/bottle-<colour>/v01/skin.json
public/textures/<full-sha256>.png
shared/bottleSkins.json
models/bottle/skin-delivery-v01.json
```

`shared/bottleSkins.json` — общий разрешённый реестр frontend / backend:
геометрия, её hashes, список скинов, revision, пути и hashes manifest.
`skin-delivery-v01.json` — измерения, provenance, параметры и исходные hashes.

## 3. Подготовка пакета

```sh
npm run models:bottle:skins
```

Скрипт [separate-bottle-skins.mjs](../scripts/separate-bottle-skins.mjs):

1. Сверяет входные GLB с метаданными low / HQ по SHA-256.
2. Извлекает PNG без изменения пикселей и сохраняет по полному content hash.
3. Удаляет изображения, textures / samplers и PBR-описания из geometry GLB;
   сохраняет минимальные материалы-заглушки и постоянные materialSlotId.
4. Пересобирает bufferViews / offsets без изменения геометрических данных.
5. Сохраняет UV / binding contract в extras сцены.
6. Создаёт девять manifest из существующих цветов спецификации, общий реестр
   и receipt. Числовые цвета сразу приводятся к Linear-sRGB, как в старом runtime.
7. Повторно проверяет неизменность входных файлов.

Новые изображения и материальные варианты не рисуются генератором.
Семантические слоты: `body.plastic`, `decoration`, `steel.brushed`,
`steel.handle`, `lid.bamboo`, `lid.seal`, `body.coating`.
Порядок material index и суффиксы Blender .001 не используются как постоянные ID.
Повторная подготовка текущего выпуска воспроизводима; новый выпуск получает
новые revision / hashes, неизменяемые URL не должны менять содержимое.

## 4. Формат скина и совместимость

Реальный пример: [чёрный скин](../public/skins/bottle/bottle-black/v01/skin.json).
Manifest содержит:

- `schemaVersion: 1`, `id`, `revision`;
- `compatibility`: `modelId`, `uvLayout`, `materialBindings`;
- `materials`: массив glTF-подобных PBR-описаний с `extras.materialSlotId`;
- `profiles.low` и `profiles.final`: images, textures и samplers.

У каждого изображения указаны file, полный sha256, bytes, width / height,
name и mimeType. TextureInfo хранит index, UV set и KHR_texture_transform.
PBR-параметры включают цвет, metalness / roughness, normal scale,
doubleSided / alpha, а также используемые clearcoat и anisotropy.

Оба LOD обязаны иметь одинаковый совместимый UV / binding contract.
Одна и та же карта может использоваться в нескольких скинах и слотах.
Нельзя назначить скин произвольной геометрии только по похожему имени материала.

Сейчас подключён профиль бутылки с семью слотами и девятью известными цветами.
Общие кеш / очередь / адаптер пригодны для дальнейшего расширения; другие
товары требуют собственного реестра совместимости, привязок и проверок.
Полный перенос других моделей остаётся отдельной работой.

## 5. Клиентский загрузчик и материалы

[skinLoader.ts](../src/skinLoader.ts) отвечает за manifest, карты, материал и
привязку к модели; [skinResources.ts](../src/skinResources.ts) — за общий кеш,
lease / reference count, очередь и отмену.

JSON и PNG проверяются по ожидаемым байтам и полному SHA-256 перед применением.
У PNG дополнительно проверяются размеры. Изображения декодируются с явно
заданными orientation / premultiply / colour conversion; параметры Texture
повторяют GLTFLoader. Клиенту нужны WebCrypto (crypto.subtle) и createImageBitmap. Локально проверен
localhost; production-страницу следует обслуживать по HTTPS.
Внешние зависимости внутри GLB по-прежнему запрещены.
SkinLoader получает только пакеты из разрешённого реестра.

Материалы MeshStandardMaterial / MeshPhysicalMaterial сохраняют:

- Linear-sRGB факторов и sRGB цветовых карт; normal / roughness / metalness без sRGB;
- каналы glTF metallic-roughness: G для roughness, B для metalness;
- sampler / mipmap, anisotropy текстуры, UV set, offset / repeat / rotation;
- clearcoat и anisotropy материала, нормали и прежний патч мягких теней.

Важная совместимость: GLTFLoader инвертирует Y normalScale и
clearcoatNormalScale на сетке без готовых тангентов. Адаптер делает то же
при создании и смене материала, отдельно учитывает vertex colours / flat shading.
Без этого файл текстуры тот же, а микрорельеф визуально меняется.

Каждая модель владеет собственными стабильными material objects. При смене
скина их параметры копируются, поэтому уже созданный rig, использующий эти
материалы, обновляется без пересоздания. `configureSourceModel` не переписывает
цвет и roughness материалов с флагом externalSkin. Логотип остаётся отдельным
слоем print_surface, материал скина его не заменяет.

Проверены текущие непрозрачные скины бутылки. Адаптер читает базовые PBR-карты,
AO / emissive и используемые physical-поля; неизвестные material extensions
отклоняются. Произвольный shader, transmission, новая геометрия или другой
набор классов материалов не считаются автоматически совместимым скином.

## 6. Low → final и смена скина

Порядок начальной загрузки:

1. Загрузить low GLB и нужный low-профиль выбранного скина.
2. Применить материалы, подготовить сцену, показать low и завершить ready.
3. После фактического показа начать final GLB и final-карты с низким приоритетом.
4. Подготовить GPU и шейдеры, проверить актуальные skinId / revision / generation.
5. Дождаться завершения команды, предметной / камерной анимации и жеста.
6. Заменить отображаемую сборку и плавно проявить карты за 320 мс;
   при reduced motion сразу применить конечный материал.

Камера, OrbitControls, WebGL-контекст, поза и логотип сохраняются.
Геометрия заменяется сразу; смешиваются карты, геометрический morph не добавлен.

При setSkin новый набор готовится отдельно. Старый остаётся видимым до успеха.
Проверяется совместимость, подготавливаются программы для фактических свойств
геометрии; временные подготовленные материалы удерживаются до первого показа
новых, чтобы GPU-программа не уничтожалась перед применением.
Promise завершается после применения и кадров отрисовки.

Новый вызов отменяет ещё не применённый предыдущий; устаревший результат
отклоняется с AbortError. Камера и состояние не сбрасываются. Выбор на low
сохраняется после поздней загрузки final. При смене во время подготовки final
устаревший переход переподготавливается, а не возвращает старый скин.

Ошибка нового скина оставляет прежний рабочий вид и отклоняет Promise.
Ошибка final оставляет low. Ошибка начального low-скина отклоняет ready и
показывает ошибку. При закрытии viewer отменяются запросы и освобождаются
его материалы / leases; запоздавшие результаты не применяются.

Диагностика viewer: data-skin, data-skin-revision, data-skin-status
(ready / loading / waiting-idle / failed) и прежние data-quality / тайминги.
Дополнительных элементов управления качеством нет.

## 7. Кеш, очередь и владение ресурсами

PNG и manifest имеют собственные версии / hashes. Production-раздача PNG
с hash в имени сообщает `Cache-Control: public, max-age=31536000, immutable`;
остальные файлы сохраняют no-cache. Обновление описания скина не требует
повторной геометрии, новый цвет может использовать уже загруженные карты.

Кеш разделён:

- manifest — по полному hash, до 16 неиспользуемых записей;
- декодированное изображение — по content hash, мягкий лимит 16 MiB / 32 записи;
- Texture view — по hash + sampler + UV-transform / set + colorSpace,
  мягкий лимит 16 MiB / 64 записи.

LRU освобождает только ресурсы без потребителей; активные leases не удаляются
ради лимита. Это ограничение удерживаемого кеша, не обещание потолка всей
GPU-памяти сцены. Texture.dispose и ImageBitmap.close выполняются раздельно:
общий bitmap закрывается после освобождения всех нуждающихся в нём views.
Материалы отдельных моделей не делятся; общие Texture views не изменяются
после выдачи. Новому sampler / transform соответствует отдельный view.

Общие skin-запросы ограничены двумя одновременно. Ожидающая интерактивная
работа имеет приоритет перед фоновой. GLB использует прежний отдельный
транспорт диапазонов. fetch priority остаётся подсказкой браузеру.
Таймаут skin-ресурса — 30 с после начала запроса; автоматического бесконечного
повтора нет. При повторном setSkin после ошибки выполняется новая попытка.
Отмена одного потребителя не прерывает общий ресурс другого; отмена последнего
останавливает fetch, а поздний decode освобождается.

Сервер каждый PNG создаёт в новом browser context; пользовательский кеш и GPU-
ресурсы между такими context не разделяются автоматически.

## 8. Публичный API

```js
const app = window.appName3DVisualisation;
await app.ready;
const skins = app.getSkins(); // id, revision, подписи de/en
await app.setSkin({ id: 'bottle-red', revision: 'v01' });
const selected = app.getSkin();
await app.setState('open');
const png = await app.getCurrentViewAsImage();
```

Доступны bottle-black, bottle-blue, bottle-red, bottle-white, bottle-green,
bottle-orange, bottle-turquoise, bottle-silver, bottle-navy, revision v01.
Нужно передавать id и revision; неизвестные значения отклоняются до загрузки.
getSkin возвращает применённый скин. Прежние setState, setCamera, getViews,
getCamera и экспорт сохранены. Все изменяющие вызовы используют очередь API;
скин и параметры PNG читаются согласованно.

## 9. Серверный PNG

Текущий запрос использует version 5 и обязательное поле:

```json
{ "skin": { "id": "bottle-red", "revision": "v01" } }
```

Остальные поля — product, state, фактическая camera и image — описаны в
[BOTTLE_API.md](BOTTLE_API.md). Version 3 также содержит fingerprint отдельно
доставленной [сцены](SCENE_DELIVERY.md). Сырой version 1 без skin поддерживается как
фиксированный чёрный вид; skin в version 1 отклоняется. Version 2 без skin,
неизвестные id / revision или неподдерживаемая версия запроса получают ошибку.
Version 1 / 2 используют сохранённую студию v01 без поля scene.
Version 4 также передаёт [состав композиции](COMPOSITION_CAMERAS.md). Сейчас
подготовленные экземпляры бутылки используют общий выбранный скин и состояние,
индивидуальные преобразования и собственные rig / нанесения.

Backend использует тот же реестр и SkinLoader, загружает final-геометрию и
final-профиль. Worker сообщает фактически применённый скин, сервер проверяет
его совпадение с запросом вместе с камерой. Заголовок X-Render-Skin содержит
например `bottle-red@v01`. При недоступности нужного скина возвращается ошибка,
другой default не подставляется. Клиентский снимок Canvas не используется.

Поле URL / HTML / shader не управляет ресурсами worker; разрешён собственный
origin. Внутренний __bottleRender имеет фиксированные варианты эталона только
для визуального QA; HTTP-контракт такой выбор не передаёт.

## 11. Почему выбран этот способ и что остаётся

glTF допускает изображения по URI или через bufferView, поэтому разделение
не запрещено форматом. [Официальная схема Image](https://raw.githubusercontent.com/KhronosGroup/glTF/main/specification/2.0/schema/image.schema.json).
Собственный manifest даёт независимую поставку материалов и явные профили
low / final, сохраняя строгую самодостаточность GLB геометрии.

KHR_materials_variants описывает подготовленные варианты внутри glTF и
сопоставление материалов примитивам; это отдельная возможность обмена,
не обязательная для нашего загрузчика. [Спецификация](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_variants/README.md).

Дальше по [общему стандарту](MODEL_DELIVERY_STANDARD.md) нужно перенести старый
каталог / пару и остальные товары. Для каждого проверяются UV / slots, rig,
карты и возможности material adapter. Изменение силуэта требует геометрии,
а не одного скина. Произвольные пользовательские логотипы для серверного PNG
также требуют отдельного механизма доставки; текущая страница использует
демонстрационное нанесение. Новых публичных загрузок и внешних сервисов эта
реализация не добавляет.
